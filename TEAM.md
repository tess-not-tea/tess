# TEAM.md

## Как мы работаем

### 1. Основной принцип

GitHub — источник правды по работе проекта.

- Issues — задачи.
- GitHub Project — текущее состояние работы.
- Pull Requests — изменения в коде.
- Telegram — оперативное общение.
- Discord — еженедельная совместная работа и синхронизация.

Важные решения и результаты не должны оставаться только в Telegram или Discord.

---

## 2. Недельный цикл

Рабочая итерация:

**четверг → следующий четверг**

В четверг на университетском стендапе каждый кратко рассказывает:

- `DONE` — что закончено;
- `NEXT` — что будет сделано к следующему четвергу;
- `BLOCKED` — что мешает работе.

После стендапа актуализируем задачи текущей недели в GitHub Project.

---

## 3. GitHub Project

Все активные задачи должны находиться в `Tess Development`.

Используем статусы:

- `Backlog` — задача ещё не готова к работе;
- `Ready` — можно брать;
- `In Progress` — работа идёт;
- `Review` — работа закончена и ждёт проверки;
- `Blocked` — есть внешний блокер;
- `Done` — задача завершена.

У активной задачи должны быть:

- Assignee;
- Iteration;
- Area;
- Priority.

GitHub Project должен отражать реальное состояние работы.

---

## 4. Issues и sub-issues

Issue — основная единица работы.

Крупные задачи и исследования можно оформлять как parent issue, а конкретную работу — как sub-issues.

Пример:

```text
Research: target audience
├── Research — Alice
├── Research — Bob
├── Research — Charlie
└── Synthesize findings
```

У каждого sub-issue один основной Assignee.

---

## 5. Ответственность

У каждой задачи есть один ответственный.

Ответственный:

  - двигает задачу до результата;
  - обновляет её статус;
  - сообщает о блокерах;
  - создаёт PR, если задача связана с кодом;
  - просит review.
  - 
Помощь других участников приветствуется, но ownership остаётся у одного человека.

---

## 6. Blockers

Если задача заблокирована:

  1. перевести её в Blocked;
  2. написать причину в issue;
  3. сообщить команде.
  4. 
Не ждём следующего стендапа, если проблему можно начать решать раньше.

---

## 7. Коммуникация

### Telegram

Используем для:

  - быстрых вопросов;
  - коротких обсуждений;
  - уведомлений;
  - просьб о помощи.

### Discord

Раз в неделю проводим совместную рабочую сессию.

Цель:

  - синхронизироваться;
  - поработать вместе;
  - интегрировать части проекта;
  - решить сложные вопросы.
    
### GitHub

Используем для:

  - задач;
  - результатов работы;
  - документации;
  - PR;
  - решений, которые должны сохраниться в истории проекта.

---

## 8. Работа в команде

  - Критикуем решение, а не человека.
  - Не скрываем проблемы.
  - Просить помощь — нормально.
  - Не оцениваем вклад количеством коммитов или строк кода.
  - Не ждём указаний лида для каждого следующего шага.
  - Если виден логичный следующий шаг, участник может предложить и взять его сам.

---

## 9. Цель лида

Задача Team Lead — не контролировать каждое действие, а:

  - поддерживать ясность приоритетов;
  - замечать блокеры;
  - помогать синхронизировать части проекта;
  - постепенно делегировать больше решений команде.
