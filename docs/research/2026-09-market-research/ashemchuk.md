### Slowly

#### Тип бизнеса и пользовательские сценарии 

Студия растяжки. Приложение для записи на занятия, оплаты абонимента, отслеживания расписания. Пользователям так же направляются уведомления о проходящих мероприятиях. Есть возможность поставить оценки тренерам, увидеть среднюю оценку.

#### Экраны

- Главный
    Содержит переходы на другие экраны, карусель с актуальными постами, колонки с актуальными занятиями и тренерами

![Главная](image.png)

![Посты или сторис](image-14.png)

- Расписание
    Расписание занятий по дням недели. Каждую запись можно открыть, увидеть подробную информацию (тренер, описание занятия, информацию о том, что нужно взять с собой, сложность занятия) и записаться, если есть места и занятие еще не началось

![Расписание занятий](image-1.png)

![Запись](image-15.png)

- Тренеры
    Представлены тренеры с фото, описанием деятельности, оценкой. Можно подробнее прочитать про тренера: расписание, запись на персональную тренировку, отзывы (с возможностью его написать), информация о тренере
![Тренеры](image-2.png)

![Тренер](image-16.png)

- Профиль
    Информация о пользователе и меню:
    - Личные данные: можно изменить фото и контактную информацию
    - Мои записи: просмотр записей в виде списка с фильтром прошедшие/ближайшие
    - Мои абонименты: выглядит как предыдущий пункт. На iOS нет возможности оплатить абонимент и посмотреть какие они бывают
    - Уведомления
    - Slowly: контактная информация, юр адрес
    - Как это работает
    - О приложении

### Санитас

#### Бизнес

Частная клиника. Не малый бизнес. Согласованность с ПО на компьютерах врачей и регистратуры. Бизнес не наша целевая аудитория, так как продукт слишком комплексный. Рассматриваю только приложение для пациента.

#### Экраны

- Главный
    - Запись онлайн
    - Ближайшие приемы в виде списка карточек приема: дата, время, специалист, точный адрес, особые условие(наличие направления от врача или ни есть ни пить перед сдачей крови)
    - Финансы: накопленные бонусы, скидки
    - Данные в медкарте

![Главная](image-4.png)

- Приемы
    - Список карточек приема. содержание карточек описано выше. Разделение на прошедшие и будущие приемы
    - Оценка для каждого приема
    - Возможность подтвердить прием в приложении (без звонка из клиники)
    - кнопка Записаться онлайн(почти на каждом экране)

![Приемы](image-5.png)

- Медкарта
    - Данные о прошедших приемах: дата, специалист, заключение специалиста, рекомендации. Заключение врач собирает в процессе приема в ПО на компьютере, отдает на руки в виде распечатанного документа с печатью и подписью, такой же документ появится в ЛК.

![Медкарта](image-6.png)

- Еще
    Список из информации о пользователе и прочем бюрократическом
![Еще](image-7.png)

- Запись на прием
    - Поиск по врачу, специализации, услуге
    - фильтрация по филиалу
    - расписание с датами и временем
    - форма для записи заполняется автоматически (паспортные данные, контактная информация)
![Запись на прием](image-13.png)

## Общие паттерны

### Навигация

Во всех рассмотренных приложениях главный экран используется
как точка входа в ключевые пользовательские сценарии.

Часто используются:

- tab navigation;
- переход list -> details;
- быстрые действия с главного экрана.

### Контент

Повторяется формат свободного информационного контента:

- новости;
- акции;
- сторис;
- изображения;
- текстовые публикации.

### Lists and Cards

Большая часть данных отображается через списки карточек:

- занятия;
- тренеры;
- приемы;
- филиалы;
- товары/меню.

Карточка обычно содержит:

- изображение;
- название;
- дополнительную информацию;
- статус;
- действие.

### Scheduling / Booking

В Slowly и Санитас повторяется один сценарий:

Resource
→ availability
→ date/time
→ booking.

Это потенциально универсальная capability Tess.

### Filtering and Search

Используются:

- поиск;
- фильтрация по филиалу;
- фильтрация по времени;
- фильтрация прошедшие/будущие.

### User Profile

Типовой набор:

- личные данные;
- история действий;
- записи;
- подписки/абонементы;
- уведомления;
- настройки.

### Ratings and Reviews

Встречаются оценки:

- тренеров;
- приемов.

Потенциально универсальные компоненты:

- Rating;
- Review List;
- Review Form

## Повторяющиеся модели данных

### User

Практически любое приложение содержит пользователя и его профиль.

### Location

Филиалы / места предоставления услуг.

### Service

Услуга, занятие, прием и т.п.

### Person / Provider

Тренер, врач, специалист.

### Booking

Связь:
User + Service + Provider + Date/Time.

### Content

Новость / пост / акция / сторис.

### Review

Оценка и пользовательский комментарий.

## Потенциально сложные для Tess сценарии

### Scheduling

Расписание зависит от:
- доступности специалиста;
- времени;
- количества мест;
- уже существующих записей;
- состояния события.

### Loyalty

QR → получение чека → применение акции → начисление баллов.

Это уже workflow из нескольких сущностей и условий.

### External systems

Санитас показывает важную проблему:
часть данных создается не внутри мобильного приложения,
а во внешней медицинской системе.

Tess в будущем может потребовать интеграции с внешними API.

### Maps

Требуют native capability и работы с координатами.

### Payments

В приложениях присутствуют/подразумеваются оплаты и абонементы.
Это отдельная сложная интеграционная область.
