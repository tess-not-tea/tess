## FlutterFlow

FlutterFlow — low-code платформа для создания нативных iOS/Android/Web приложений поверх настоящего Flutter-кода. Представляет полюс **UI-first** в паре с Glide (data-first).

### Общее описание

#### UI

Визуальный drag-and-drop builder, работающий напрямую с деревом Flutter-виджетов (Row, Column, Stack, ListView и т.д.) — высокая точность контроля над layout ценой более высокого порога входа. Библиотека из 200+ готовых виджетов, переиспользуемые Components, импорт тем из Figma. Widget Builder Parameters позволяют передавать произвольный UI внутрь компонента как слот — механика, близкая к `children`/`slot` в обычной разработке. Storyboard визуализирует все экраны и переходы между ними как единый граф.

#### Logic

Поведение строится через визуальный **Action Flow Editor** — граф действий (create/update/delete/fetch данных, навигация, диалоги), привязанных к событиям UI. Condition-логика встроена как ветвления внутри Action Flow и как Conditional Visibility на уровне отдельного виджета. Отдельного понятия workflow нет — вся автоматизация выражается через Action Flow плюс серверные Google Cloud Functions для фоновой/бэкенд-логики.

#### Data

Нативная интеграция с Firebase (Firestore, Auth, Storage) и Supabase, произвольные REST API, собственные Custom Data Types, глобальное состояние приложения через App Values.

#### Mobile

Приложение — реально компилируемый Flutter-код (iOS/Android/Web из одной кодовой базы), а не обёртка. Доступ к камере, геолокации и т.п. — через готовые интеграции или custom code. Push-уведомления — через Firebase Cloud Messaging, с нетривиальной ручной настройкой прав в Firebase Console (частый источник проблем у пользователей).

#### Preview / Publishing

Live preview прямо в браузере, отдельный Test Mode для отладки с реальными данными. Часть нативной функциональности (в первую очередь push) нельзя полноценно протестировать внутри платформы — нужно реальное устройство. Возможен экспорт Flutter-кода проекта целиком.

#### Идеи для Tess

- визуализация дерева компонентов и общего графа навигации (Storyboard) — делает архитектуру приложения прозрачной для пользователя;
- Widget Builder Parameters (слоты в компонентах) — сильный кандидат на универсальный компонент Tess, резко повышает переиспользуемость библиотеки;
- Action Flow как единая модель actions + conditions в одном визуальном графе, привязанном к событиям;
- экспорт кода/схемы как anti-lock-in стратегия;
- отдельное место для серверной логики (Cloud Functions), не привязанной к конкретному экрану.

#### Потенциальная точка развития для Tess

> Генерация полноценного нативного кода "под капотом" — это фундаментальное архитектурное решение, а не фича. Если Tess не строится поверх компиляции в нативный код, тот же уровень производительности и app-store-совместимости, что у FlutterFlow, будет сложно повторить.

## Glide

Glide — no-code платформа, превращающая таблицу данных (Google Sheets, Airtable, Excel, собственные Glide Tables) в готовое приложение. Представляет полюс **data-first** в паре с FlutterFlow.

### Общее описание

#### UI

Отправная точка — не экран, а источник данных: Glide анализирует структуру таблицы и сразу генерирует рабочий UI (списки, карточки, детальные экраны), который донастраивается визуально. Есть собственная база **Glide Tables** как альтернатива внешним источникам. Drag-and-drop редактор с готовыми компонентами, live preview сразу для мобильного и десктопного вида. Кастомизация ограничена цветом/текстом/layout — без "пиксель-в-пиксель" контроля, как у FlutterFlow.

#### Logic

**Action buttons** выполняют одно или несколько действий (например, изменить статус записи и одновременно проставить timestamp). Видимость компонентов и данных настраивается через visibility conditions на уровне компонента. Для сложной автоматизации — отдельный **node-based Workflow Editor** с триггерами по времени, по изменению данных, по действию пользователя или вручную; по отзывам, менее дружелюбен к новичкам, чем остальная часть платформы.

#### Data

Данные — центральная сущность: структура таблицы почти напрямую определяет структуру приложения. Прямая синхронизация с внешним источником в обе стороны. При росте объёма данных Google Sheets как backend быстро упирается в проблемы масштабирования. AI встроен на уровне колонок данных (AI как тип колонки): генерация текста, суммаризация, извлечение данных из изображений/PDF — без отдельной надстройки.

#### Mobile

Ключевое архитектурное отличие от FlutterFlow: Glide-приложения — это **PWA**, а не скомпилированные нативные приложения. Из коробки — нативный сканер штрихкодов/QR. Существенные ограничения: частичный офлайн-режим (запись данных требует соединения), ограниченные push-уведомления, нет полноценной публикации в App Store/Google Play (есть платная обёртка PWA в нативную оболочку, которую всё чаще отклоняет модерация Apple), нет доступа к Bluetooth/NFC/фоновому GPS.

#### Preview / Publishing

Live preview одновременно для мобильного и десктопного форм-фактора, приложение по умолчанию адаптивное. Кастомного кода нет — расширение только через готовые интеграции (Zapier, QuickBooks, Stripe и др.). Экспорта в исходный код не существует — полный vendor lock-in, при росте за пределы возможностей Glide приложение переписывается с нуля на другой платформе.

#### AI

Есть встроенный AI-билдер приложения по текстовому промпту, но без отдельных режимов планирования/чата — менее гибкий, чем у некоторых конкурентов. Более сильная сторона — именно AI на уровне данных (колонки), а не на уровне генерации всего приложения.

#### Идеи для Tess

- data-first генерация первого черновика UI на основе структуры/схемы данных — быстрый старт для типовых сценариев малого бизнеса (каталог, заявки, заказы);
- AI как тип колонки/поля данных — модель для universal no-code action "обработать значение через AI", встроенная в данные, а не в отдельный сервис;
- node-based Workflow Editor с разными типами триггеров (время, изменение данных, действие пользователя, ручной запуск);
- разделение "лёгких" Action buttons и "тяжёлых" Workflows — не каждое действие должно проходить через полноценный конструктор автоматизаций.

#### Потенциальная точка развития для Tess

> Все сценарии, требующие настоящих нативных возможностей (надёжные push, офлайн-first, глубокая интеграция с оборудованием, публикация в сторы без wrapper-подхода), — системное ограничение PWA-архитектуры, а не недоработка конкретной платформы. Это стоит учитывать при выборе технологической базы Tess, если планируется конкурировать именно в mobile-сегменте.

## M3E Canvas

M3E Canvas — не no-code конструктор приложений в привычном смысле, а открытый (MIT) браузерный инструмент для скетчинга экранов в стиле Material 3 Expressive, который превращает получившийся макет в текстовый промпт для AI coding-агента (vibe-coding). Добавлен в обзор как показательный пример смежного, но принципиально иного подхода: не "построй приложение внутри платформы", а "визуально собери спецификацию — код напиши через LLM снаружи".

### Общее описание

#### UI

Drag-and-drop канвас с готовыми Material 3 Expressive компонентами: кнопки, icon buttons, FAB, chips, app bars, navigation bars, search bars, карточки, списки, диалоги, snackbars, текстовые поля, свитчи, чекбоксы, слайдеры, текст, изображения, боксы, разделители. Есть "магнитные" соединения — близко расположенные элементы (например, кнопки списка) визуально сливаются в группу. Поддерживаются множественные экраны (phone screens), каждый со своим именем и фоном.

#### Logic

Логики в привычном смысле (actions/conditions/workflows) нет вообще — единственная форма "поведения", которую можно задать, это переход по тапу: любому тап-элементу назначается целевой экран и тип transition (slide/fade/expand/none). Никакой работы с данными, состоянием или условными ветвлениями инструмент не предоставляет — это чистый UI-скетчер с навигационными связями между экранами.

#### Data

Отсутствует как концепция: инструмент не работает с моделями данных, полностью no-backend ("No backend (local storage)" — заявлено разработчиками как одна из ключевых характеристик). Всё, что связано с данными и авторизацией, полностью ложится на инструмент/агента, которому в итоге передаётся сгенерированный промпт.

#### Mobile

Сам инструмент — веб-приложение (десктоп-браузер для полной версии редактора; на телефоне доступен ограниченный режим с одним экраном и только кнопками). Никакого собственного mobile-рантайма или экспорта в приложение нет — конечный мобильный экран получает не сам инструмент, а внешний AI coding-агент, которому передаётся промпт.

#### Preview / Publishing

Preview реализован как интерактивный тап-переход между связанными экранами прямо в браузере — можно "прощупать" макет до генерации кода. "Publishing" в привычном смысле нет: результат работы — это (а) экспорт текстового промпта (на английском или японском, с пользовательскими заметками о поведении каждого элемента) и (б) экспорт отдельного экрана как PNG. Дальнейшая судьба макета (собрать реальное приложение) полностью зависит от внешнего AI-инструмента, в который вставляется промпт.

#### Идеи для Tess

- **промпт как экспортный формат**, альтернативный код-экспорту FlutterFlow: помимо кода/конфигурации, Tess может уметь выгружать компактное текстовое описание экрана/приложения — полезно как "мост" в сторонние AI-инструменты для тех пользователей, которым не хватает возможностей Tess;
- **магнитные связи элементов** (визуальное слияние соседних кнопок/списочных айтемов в группу) — любопытный UI-механизм для быстрой сборки повторяющихся паттернов (тулбары, группы действий) без ручной настройки контейнеров;
- **интерактивный tap-through preview на этапе чистого макета**, ещё до подключения данных и логики — может быть полезен как отдельный "быстрый" режим предпросмотра в Tess для самой ранней стадии проектирования экрана.

#### Потенциальная точка развития для Tess

> M3E Canvas сознательно не решает задачи, которые составляют ядро Tess (данные, actions, workflows, реальный рантайм) — он существует только на уровне UI-макета и делегирует всё остальное внешнему LLM. Это, скорее, инструмент-компаньон, а не конкурент: показывает нижнюю границу того, что вообще можно назвать "no-code app builder", и подсвечивает, что ключевая ценность Tess — не в скетчинге экрана, а именно в связке UI + данные + логика внутри одной платформы.

## Итоговое сопоставление

| | FlutterFlow | Glide | M3E Canvas |
|---|---|---|---|
| Подход | UI-first, компилируемый код | data-first, spreadsheet-to-app | UI-скетчер → промпт для LLM |
| Итоговый артефакт | нативное Flutter-приложение | PWA | нет (промпт/PNG) |
| Данные | Firebase/Supabase/REST, кастомные типы | таблицы (Sheets/Airtable/Glide Tables) | отсутствуют |
| Логика | Action Flow (граф) | Action buttons + node-based Workflows | только навигация по тапу |
| Экспорт / lock-in | экспорт Flutter-кода | нет экспорта, полный lock-in | экспорт промпта/PNG, без кода |
